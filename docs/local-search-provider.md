# Maps and Local Finder provider support

Local monitor definitions accept the 129 codes from the published Google SERP language catalog (2026-04-06 snapshot, checked 2026-10-14). Choose a search language independently of the application language. Unknown codes are rejected by the form, server definition and native request validation. The catalog does not promise that every business has results in every language.

The DataForSEO queued adapter supports Maps and Local Finder independently, with desktop/mobile, compatible OS, explicit coordinates, and depth 1..20. Maps zoom is 3..21; Finder zoom is 4..18. Each definition freezes its surface, rank scale, language, device, points and policy revision. Editing these requires a new revision and a fresh spending review. Views and exports read retained observations; they never purchase a scan.

Maps uses the provider's organic Maps group position. Finder uses `finder_group`, the original group ordinal including ad slots. Ads and unknown promotion remain visible as evidence but cannot confirm an organic target KPI. We do not renumber positions after removing ads or duplicates. Previously saved `finder_organic` definitions remain readable but require revision to `finder_group` before paid execution.

The confirmed standard Maps list estimate is 0.06 cents per task in the supported depth range. Finder has its own native POST operation and price version: 0.06 cents per ten-result page, with depth rounded up. Thus depth 20 reserves 0.12 cents per point, not the Maps 0.06-cent amount. This conservative bound follows the current pricing page and task documentation. The older July help article states twenty results per desktop page; the upper bound covers that conflict for both devices. Actual charges, partial failures, unknown acceptance and refunds are recorded from provider evidence rather than replaced with the preview amount. Unsupported add-ons, paid keyword operators, priority changes and expired rates block launch.

Both surfaces use the same project/connection budgets, durable receipts, worker, collection leases, normalized history, matching and exports. A lost submission reply keeps ownership and blocks a second purchase until reconciliation. Collection uses the original surface and accepted ID, including after cancellation or rate expiry. Recurring schedules start off and require separate explicit approval. The application and worker must use this same build; no database migration or access shutdown is needed for this adapter change.

Coordinates identify a query seed, not a proven observer location. A matching response echo acknowledges that seed but never asserts exact observer geometry or complete coverage. Missing listings remain unknown without coverage proof. Legacy English Maps v1/v2 records keep their original adapter and capability versions; they are not reinterpreted as multilingual or Finder records.

Sources checked 2026-10-14: [Google languages](https://docs.dataforseo.com/v3/serp/google/languages/), [Maps task](https://docs.dataforseo.com/v3/serp/google/maps/task_post/), [Finder task](https://docs.dataforseo.com/v3/serp/google/local_finder/task_post/), [Finder results](https://docs.dataforseo.com/v3/serp/google/local_finder/task_get/advanced/), [Finder pricing](https://dataforseo.com/pricing/google-serp/google-local-finder-serp-api), [older cost guidance](https://dataforseo.com/help-center/serp-api-cost-explained).

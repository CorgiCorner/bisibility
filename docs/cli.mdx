The bisibility CLI manages projects, tracked keywords, rank checks, alerts, and
other API resources from a terminal. Use `--json` when another program consumes
the output. The current docs-tested package is `@bisibility/cli@0.7.0`.

## Install

```bash
npm install -g @bisibility/cli@0.7.0
bisibility --help
```

## Sign in and verify the connection

The hosted CLI login uses browser consent. It stores the resulting personal
access token locally, so the token does not need to be copied from the browser.

```bash
bisibility auth login --name "mbp16-cli" --scope admin --expires 90
bisibility auth status
bisibility projects list
```

`auth status` should report that you are signed in. `projects list` should
return at least the project you will use.

Choose the smallest scope needed for the work. See the
[personal access token guide](/api/personal-access-tokens) for scopes, expiry,
storage, and revocation.

Select a default project before mutating data:

```bash
bisibility config set projectId prj_a00000000000000000000000
```

## Next: add your first keyword

After the connection check succeeds, add a keyword and run its first check:

```bash
bisibility keywords add "headless cms" --device desktop --country "United States"
bisibility check run kw_b00000000000000000000000 --json
```

The completed response includes the current and previous position:

```json
{
  "position": 7,
  "previous_position": 10,
  "status": "completed"
}
```

Run `bisibility <command> --help` for command-specific options. Provider
credentials are connected during product onboarding and are not part of the CLI
first-run sequence.

## Command reference

For every command and flag in the inspected release, use the generated
[CLI command reference](/cli/reference). Its version and artifact source are
listed in [released client support](/compatibility).

`cloud` in CLI identifiers refers to the hosted service. The user-facing
product term is **hosted beta** during the open beta.

Administrative commands require a credential with the matching scope. Create
commands for API keys, personal tokens, and migration tokens print raw
credentials once. Store them securely.

See [Versioning and support](/versioning) for how CLI versions relate to the
app and REST API.

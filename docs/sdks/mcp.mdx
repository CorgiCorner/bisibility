An MCP server lets an MCP-compatible AI client call bisibility operations as
tools instead of composing HTTP requests itself.

## Install

```bash
npm install @bisibility/mcp@0.10.0
```

The current docs-tested package is `@bisibility/mcp@0.10.0`. See
[Versioning and support](/versioning).

## Authenticate

The local stdio server reads the API root and credential from its environment:

```bash
export BISIBILITY_API_KEY="your-api-key"
export BISIBILITY_BASE_URL="https://<region-host>/api/v1"
```

It accepts project API keys and
[personal access tokens](/api/personal-access-tokens).

The hosted Streamable HTTP server is available at:

```text
https://bisibility.com/api/mcp
```

Tools that spend provider money are listed in [Paid MCP tools](/agents/paid-tools).
Scopes and the consent screen are in [Agent permissions](/agents/permissions).

MCP clients that support OAuth discover the authorization flow automatically.
bisibility uses Authorization Code with PKCE, dynamic client registration, and
access tokens bound to the MCP resource. API keys and personal access tokens
remain available for clients that manage bearer credentials directly. For how
each client differs in tool visibility and approval, see
[what each client exposes](/agents#what-each-client-exposes).

### OAuth discovery and the MCP resource

In Cloud, sign-in and tool requests use different origins:

| Purpose | Address |
| - | - |
| Authorization server and token issuer | `https://eu.bisibility.com` |
| Streamable HTTP MCP resource | `https://bisibility.com/api/mcp` |
| Authorization server metadata | [OAuth discovery](https://eu.bisibility.com/.well-known/oauth-authorization-server) |
| MCP protected resource metadata | [Resource discovery](https://bisibility.com/.well-known/oauth-protected-resource/api/mcp) |

Start with the resource metadata and follow its `authorization_servers` value.
The authorization server metadata supplies the registration, authorization,
token and signing-key endpoints. Register the client's redirect URI, then use
Authorization Code with **PKCE S256**. Public clients do not need a client secret.

Request the advertised MCP URL as the OAuth `resource`. The access token's
`aud` must include that resource; the issuer origin alone is not the audience.
Send the access token to the MCP resource, and use the issuer's token endpoint
to refresh it. The consent screen delegates `read`, `write` or `admin` access
within the signed-in user's project permissions.

Self-hosted instances use their own app origin for both sign-in and MCP. Discover
their metadata instead of copying Cloud addresses. See
[Authentication](/authentication#oauth-for-mcp) for the credential differences.

## HTTP failures

The Streamable HTTP endpoint returns JSON-RPC error envelopes for caught application
failures, with `Cache-Control: no-store` and an `X-Bisibility-Request-Id` for support.
Authentication challenges, rate-limit headers and HTTP statuses remain meaningful:
`401` requires authentication, `403` refuses access, `426` requires a client update,
and `429` enforces a rate limit. SDK parse and validation errors retain their codes.

Transient dependency failures before tool dispatch return `503`; unexpected failures
return `500`. A `Retry-After` header does not establish that replaying a tool is safe.
After dispatch, an operation may have completed even if its response failed. Check its
outcome before retrying mutating or paid work.

The application allows 30 seconds for authentication and transport setup, and 260
seconds overall. Live search-performance query reads default to a 25-second provider
deadline (`ANALYTICS_READ_TIMEOUT_MS`, from 1000 to 120000 milliseconds). Invalid
configuration retains the default. A provider timeout returns a `504` API problem inside the usual MCP tool
error result; caller cancellation does not mark the connection for reauthorization.
Runtime termination, framework startup failures and upstream responses can still
produce a non-JSON response outside this application boundary.

## Start the local server

This copyable quickstart starts the docs-tested stdio server.

```bash
export BISIBILITY_API_KEY="your-api-key"
export BISIBILITY_BASE_URL="https://<region-host>/api/v1"

npx -y @bisibility/mcp@0.10.0
```

Point your MCP client at that stdio command. The first useful read is the
`list_projects` tool, which performs
[`GET /projects`](/api-reference/projects/list-projects-visible-to-this-api-key).

The [complete MCP example](https://github.com/CorgiCorner/bisibility/blob/main/examples/mcp/quickstart.mjs)
starts the server and calls `list_projects`.

## Track AI observations and save an analysis

Start with `get_project_context` and `get_ai_research_catalog`, then inspect saved topics,
prompts, runs and samples. `get_prompt_tracker_history`, `get_prompt_tracker_trends` and
`export_prompt_tracker_evidence` retain coverage, source identity and continuation metadata.
They read stored evidence without purchasing a new observation.

Prompt Research finds questions to track. Today that is model-generated suggestions to
review. `prompt_research_suggestions_preview` reviews the complete context, competitors,
model and market without paid work. `prompt_research_suggestions_generate` requires write
scope, the unchanged preview, explicit own-key actual-cost consent and a stable UUID retry
key. The returned drafts are editable hypotheses. Accepting one creates a Prompt Tracker
prompt and preserves its verified generation reference. It does not launch a baseline or
activate a schedule.

Use `create_agent_report` to save an approved analysis with its sources and limitations.
A read-only connection can review stored data but cannot save a report or generate drafts.
See [Prompt Tracker](/guides/prompt-tracker) and [Agent Reports](/guides/agent-reports).

## Interpret research results

For application API responses, read [rank coverage](/serp-observations#read-a-completed-check)
before treating a null position as absence within the requested depth.
Execution status and observation completeness describe different facts.

[Backlinks](/api/backlinks#partial-history) documents successful snapshots with
unavailable history and [failed summary evidence](/api/backlinks#unconfirmed-history-cost).
The latter remains an error response with unknown total cost, rather than a
successful reusable snapshot. Consult [client compatibility](/compatibility)
for the support verified for your installed package version.

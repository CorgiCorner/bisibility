An MCP server lets an MCP-compatible AI client call bisibility operations as
tools instead of composing HTTP requests itself.

## Install

```bash
npm install @bisibility/mcp@0.10.0
```

The current docs-tested package is `@bisibility/mcp@0.10.0`. See
[Versioning and support](/versioning).

## Authenticate

The local stdio server reads the API root and credential from its environment:

```bash
export BISIBILITY_API_KEY="your-api-key"
export BISIBILITY_BASE_URL="https://<region-host>/api/v1"
```

It accepts project API keys and
[personal access tokens](/api/personal-access-tokens).

The hosted Streamable HTTP server is available at:

```text
https://bisibility.com/api/mcp
```

MCP clients that support OAuth discover the authorization flow automatically.
bisibility uses Authorization Code with PKCE, dynamic client registration, and
access tokens bound to the MCP resource. API keys and personal access tokens
remain available for clients that manage bearer credentials directly.

## Start the local server

This copyable quickstart starts the docs-tested stdio server. It does not
include the repository's tool-parity assertions.

```bash
export BISIBILITY_API_KEY="your-api-key"
export BISIBILITY_BASE_URL="https://<region-host>/api/v1"

npx -y @bisibility/mcp@0.10.0
```

Point your MCP client at that stdio command. The first useful read is the
`list_projects` tool, which performs
[`GET /projects`](/api-reference/projects/list-projects-visible-to-this-api-key).

The [complete MCP example](https://github.com/CorgiCorner/bisibility/blob/main/examples/mcp/quickstart.mjs)
starts the server, checks advertised tools against the HTTP contract, and
calls `list_projects`.

---
title: "Competitors"
description: "Manage the competitor domains tracked for a project."
---

Paths are relative to `/api/v1`. All routes use a project-scoped API key -
`Authorization: Bearer <api_key>` - that must belong to the project in the
path. See [Authentication](/authentication) for scopes.

| Method | Path | Purpose |
| - | - | - |
| `GET` | `/projects/{project_id}/competitors` | List managed competitors. |
| `POST` | `/projects/{project_id}/competitors` | Add a competitor domain and label. |
| `DELETE` | `/projects/{project_id}/competitors/{competitor_id}` | Remove a competitor through the project-scoped route. |
| `DELETE` | `/competitors/{competitor_id}` | Remove the same resource through the short route. |

Competitor metrics are derived from rank-check results. Adding a competitor does
not trigger a provider request by itself.

Reports compare one market at a time. A market is a location and language pair,
plus the selected device for the report. Language-qualified locations remain
separate: results for `ES` (Spanish) are not combined with `ES@en` (English).
Share of voice needs search-volume data, so a tracked market whose language is
not supported by Research remains available for position checks but is disabled
in the competitor market selector. See [Markets and languages](/markets).

The generated
[OpenAPI JSON](https://bisibility.com/api/v1/openapi.json) remains the
machine-readable source of truth for request and response schemas.

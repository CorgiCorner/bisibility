API-key routes require an admin-capable credential. Exact request and response
schemas live in the **API Reference** tab.

A personal access token can manage keys for an explicit project through
`POST /projects/{project_id}/api-keys`. Its effective permission for that
project must be `admin`. The top-level `/api-keys` aliases remain useful for
project keys and for a PAT when project selection is unambiguous.

## Token lifecycle

The raw token is returned only in the create response. This applies to both
`createApiKey` and `createProjectApiKey`. Store `token` immediately. It is not
returned again. List and revoke responses expose `prefix` and `masked_value`,
never the raw secret.

`scope` accepts `read`, `write`, or `admin`; omitting it defaults to `admin`
for backward compatibility. `expires_in_days` accepts `30`, `90`, `365`, or
`null` for no expiry.

`revokeApiKey` accepts `key_id` with or without the `key_` prefix. The response
is the revoked API-key resource with `revoked_at` set.

For CI automation with a PAT, create the project key through
`POST /projects/{project_id}/api-keys` instead of inferring the project.

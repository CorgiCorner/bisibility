title: "Analytics"
description: "Read complete search-performance totals, stored traffic snapshots, live query statistics, and synchronize analytics."
---

All paths are relative to `/api/v1` and require a bearer key scoped to the
project. Live query reads and synchronization use the project's own connected
analytics accounts. Provider rate limits and reauthorization rules still
apply.

## List page traffic snapshots

```http
GET /projects/{project_id}/analytics/traffic-snapshots?start_date=2026-06-01&end_date=2026-06-30&path=/pricing&limit=50&offset=0
```

`start_date` and `end_date` are required inclusive ISO dates. Repeat `path` to
filter up to 50 page paths. `limit` defaults to 50 and has a maximum of 200.
The response contains `rows`, `total_count`, and `offset`; each row includes
the stored provider, path, date, window, sessions, visitor, engagement, event,
duration, and scroll metrics.

## Get complete search-performance totals

```http
GET /projects/{project_id}/analytics/totals?start_date=2026-06-01&end_date=2026-06-28&compare_previous=true
```

`start_date` and `end_date` are required inclusive Pacific calendar dates. A
window contains at most 366 days. `compare_previous` defaults to `false`; set
it to `true` to include the immediately preceding equal-length window.

The response contains `current` and optional `previous` totals for web search
across all queries, pages, countries and devices. CTR is clicks divided by
impressions; position is impression-weighted. Summing a capped query list can
undercount totals, including queries withheld by the provider's privacy rules.

`source` is `stored` only when successful finalized aggregate import coverage
proves the entire requested span. Otherwise both periods use one live date-only
request. This read never starts an import or shifts the requested dates.
`data_start_date` and `data_end_date` identify returned days with impressions,
or are null when none were returned. Each period includes `freshness` with
`data_state`, `fetched_at`, `finalized_through` and `first_incomplete_date`.
A null finalized-through date means unknown finalization; absence of an
incomplete date alone does not prove finality. Stored `fetched_at` is a
conservative persistence timestamp for the covering aggregate requests.
A current, connected Search Console property is required for either source.

## List live search-performance query statistics

```http
GET /projects/{project_id}/analytics/query-stats?start_date=2026-06-01&end_date=2026-06-30&connection_id=conn_a00000000000000000000000&query=rank%20tracker&limit=100
```

`connection_id` and `query` are optional. bisibility prefers the primary
eligible connection when no connection is selected. `limit` defaults to 100
and has a maximum of 1000. The response returns the selected connection and
rows with query, optional page, clicks, impressions, CTR, and average position.
This is a live provider read, not a stored snapshot query.

## Synchronize analytics now

```http
POST /projects/{project_id}/analytics/sync
Idempotency-Key: analytics-sync-001
```

This runs the same audited project synchronization used by the app and returns
per-connection run status plus fetched, matched, and upserted row counts. A
project in read-only migration mode cannot start a sync.

A keyword belongs to a project and identifies a search phrase, market, device,
and target URL. A market is a location and language pair. Exact request and
response schemas live in the **API Reference** tab.

`device` is `desktop` or `mobile`. `frequency` is `paused`, `manual`, `daily`,
`weekly`, `monthly`, or `custom_cron`. Every keyword resource reports
`language_code` and `language_label` alongside the canonical `location_key`.

`location_key` accepts an optional `@language` qualifier such as
`ES/Andalusia/Malaga@en`. An unqualified key uses the country's default
language. Supplying the default explicitly is an alias of the unqualified key,
so `ES` and `ES@es` resolve to the same canonical market. Use the codes listed
under [Markets and languages](/markets).

## List filters

`listKeywords` pages with `limit` (default `50`, maximum `200`) and `cursor`.
`search` or `q` is a case-insensitive text search.

| Query | Description |
| - | - |
| `filter[device]` or `device` | `desktop` or `mobile`. |
| `filter[location_key]` or `location_key` | Exact canonical location key, optionally qualified with `@language`. |
| `filter[country]` or `country` | Canonical country names and aliases, case-insensitive. Deprecated: send `location_key` instead. Accepted until bisibility 0.24.0, then removed. |
| `filter[tag]` or `tag` | Case-insensitive exact tag match. |
| `filter[topic]` or `topic` | Case-insensitive exact topic match. |
| `filter[intent]` or `intent` | Case-insensitive exact intent match. |
| `filter[position_gt]` or `position_gt` | Rank-check position greater than this number. |
| `filter[position_lt]` or `position_lt` | Rank-check position less than this number. |
| `sort` | `created_at`, `-created_at`, `keyword`, `-keyword`, `text`, `-text`, `updated_at`, `-updated_at`. |

## Match texts across markets

`matchProjectKeywords` looks up up to 50 exact tracked texts across their
markets. Each request text is trimmed and lowercased before matching.
`matched_text` contains that normalized value, so use it to join each response
row to the normalized request. `text` remains the stored keyword text and can
differ in case and whitespace.

At most 100 market rows are returned for each `matched_text`. The response
always includes `meta.truncated_texts`; a normalized text listed there has more
matching markets and its returned rows are partial.

## Create keywords

`addKeywords` accepts one keyword object, an array of keyword objects, or an
object with a `keywords` array. String entries in `keywords` are converted to
`{ "keyword": "..." }`.

`keyword` is required (1 to 180 characters). `location_key` is the primary
location reference and takes precedence over the deprecated `country`,
`language`, `location`, and `city` fields. Those legacy selectors are accepted
until bisibility 0.24.0, then removed. Unresolved cities fall back to
country-level tracking with a warning.

`tags` accepts up to 12 tags, each 1 to 48 characters. Within `schedule`,
`jitter_minutes` must be a whole number from `0` to `120`. Omitting it uses
`60`; `0` disables jitter. Use `cron_expression` with `frequency: "custom_cron"`.
Daily and weekly schedules use a stable, keyword-specific interval phase, so
`timezone` does not move their phase. `timezone` anchors monthly and custom
cron schedules to wall-clock time.

The response status is `201` when at least one keyword is created. Duplicate
keyword, location, and device combinations are skipped. If location resolution
degrades, the response includes per-result `warning` values and a top-level
`warnings` array with unique warning messages.

## Update and identity

`getKeyword` returns one keyword or `404`. `setKeywordTargetUrl` patches
optional fields. Identity fields (`keyword`, `device`, `location_key`, and the
deprecated `country` / `city` / `location`) are accepted only when they match
the stored term, market, and device. A differing identity value returns `409`.
To track a different term, market, or device, add it as its own keyword and
archive the old keyword.

`tags` replaces the full tag set. `frequency` sets a default schedule with
timezone `UTC`, jitter `60`, and no cron expression. `schedule` overrides
`frequency` when both are sent.

`deleteKeyword` deletes the keyword and returns the deleted resource.

## Bulk mutate

`bulkUpdateKeywords` supports:

| Operation | Required fields |
| - | - |
| `add_tags` | `keyword_ids`, `tags` |
| `remove_tags` | `keyword_ids`, `tags` |
| `set_target_url` | `keyword_ids`, `target_url` |
| `set_frequency` | `keyword_ids`, `frequency` or `schedule` |
| `delete` | `keyword_ids` |

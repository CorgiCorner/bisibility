This path gets a self-hosted project from an empty install to its first Google
rank data. It assumes you run the app yourself and bring your own SERP provider
credentials.

**Read the deployment overview:** The steps below cover the shortest supported
self-hosting workflow.

## 1. Start the stack

Follow [Self-hosting](/self-hosting) for Docker, required services,
environment variables, migrations, and the optional Temporal worker.

For a local Docker install, the short path is:

```bash
git clone https://github.com/CorgiCorner/bisibility.git bisibility
cd bisibility
./scripts/dev/bootstrap-local.sh
docker compose -f compose.yaml up -d
```

Open `http://localhost:3000` and sign in with the demo login.

Before signing in, verify that the web process is responding:

```bash
curl -fsS http://localhost:3000/api/v1/liveness
```

Expected response:

```json
{ "status": "ok" }
```

This probe confirms only that the web process can serve requests. Use
[readiness and health](/api/discovery#liveness-and-readiness) to verify the
database contract and the optional worker before admitting production traffic.

Compose pulls version-pinned web and migration images from Docker Hub by
default. Add `-f compose.build.yaml --build` to build the checked-out web source
instead.

### Demo login

Setting `DEMO_FIXED_OTP=1` together with `DEMO_INSTANCE_INSECURE_AUTH_ACK=1`
enables a fixed demo login: email `demo@acme.dev`, one-time code `000000`. The
login screen displays both hints while demo mode is active, so you do not need
to memorize them.

This is insecure by design - anyone who knows the code can sign in. Use it only
for throwaway local installs. Remove both variables before any real deployment
and configure email delivery instead (see the
[environment variables](/self-hosting/configuration#optional-environment-variables) in
Self-hosting).

## 2. Create an account and project

After signing in, complete onboarding:

1. Create a project with a name and domain, such as `example.com`. Your root
   domain, `www`, and all subdomains count as yours. Matching is fixed today;
   per-scope control is on the roadmap.
2. Keep the default market and device unless your first tracked phrases need a
   different country, city, desktop, or mobile target.

The project domain is used to match organic Google results to your site.

## 3. Connect a SERP provider

Open **Integrations**, choose a SERP provider, then select **Connect**.

Enter the provider's credentials and select **Test connection** before saving;
credential-based, non-OAuth providers must pass the test. Connected SERP
providers are tried in priority order when a fallback is needed.

See [Integrations](/integrations) for the supported providers, their
credential fields, cost estimates, fallback priority, and the monthly budget
cap.

## 4. Add search terms

Open the tracking table, select the add action, and paste a short list with one
search term per line. Choose the location and device, add a target URL when you
know which page should rank, then select **Add & track**.

For Search Console, CSV imports, and guidance on building a larger tracking set,
see [Choose your first keywords](/guides/choose-first-keywords).

## 5. Run the first check

For the first run, open **Overview** or **Rank Tracker** and select **Run first
check**. To rerun one keyword later, open its detail page and select **Run
check**.

If you started the scheduling overlays, the worker runs due checks from the
configured schedule:

```bash
docker compose -f compose.yaml -f compose.worker.yaml -f compose.temporal.yaml up -d
```

Manual checks can run without Temporal. Scheduled checks require Temporal and the
worker.

## 6. Read results

Open **Overview** to confirm that the first check completed and produced ranking
data. Open a keyword detail page when you need the recorded position and ranking
URL.

# Retry a failed Local subset

Open an original Local run in its monitor and select the failed points to retry.
Only a native exhaustive rejection with completed accounting, or a proved never-sent
cancellation with completed accounting, is eligible. A settled canonical no-send receipt
remains settled; it is not relabelled as a release.

Review the new quote, selected task count, original task count and expiry, then confirm.
This creates a new paid run. Changing the selection or connection invalidates the preview.
The server rechecks the current actor, monitor revision, keyword/identity sources,
connection, native original proof, quote and budget before admission and first send.
A changed original source requires a new review rather than substituting current targets.

Accepted tasks, unknown acceptance, outstanding accounting and retained ownership are
not retryable. Continue collecting or reconciling their original accepted IDs. Reading,
refreshing and selecting points never calls the provider or starts scheduled work.
Repeating the same confirmed request key returns its original queued intent.

The child retains the original points and source revisions. Its grid, table and CSV/JSON
contain only selected targets; the child's coverage denominator is the selected count.
The parent run and its full denominator remain unchanged. No unselected point is inserted
as zero or unknown. Sparse points keep their original grid positions. The existing
`grid_top_n` / `sampled-grid-top-n-v1` formula and sampled unit weights are unchanged;
this subset has no comparable full-grid movement claim.

Retries need the worker, an eligible supported provider connection and the new immutable
retry schema migration. A missing capability or stale source fails closed before purchase.

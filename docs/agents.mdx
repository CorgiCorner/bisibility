AI agents can create projects, add keywords, run checks, and read rank history.
They use the same authenticated operations as other API clients.

## What an agent can do

- Connect and test a SERP provider.
- Add keywords to a project.
- Run a rank check and read the result.
- Read ranking history and stored traffic snapshots.
- Review, mute, or acknowledge triggered alerts.
- Export project data or prepare a migration.

## Use a workflow

The [skills catalog](https://bisibility.com/skills) describes available workflows.
Its chat examples are illustrations: Send plays the example, without contacting
providers or changing a project. Expand the tool trace to inspect the calls.

Project setup starts with your domain, business and audience, then proposes a
plan. Saving changes requires approval of that plan. Provider secrets belong in
secure connection settings, never in the chat. A project API key cannot create a
new project; use a personal access token with the required scope.

Workflows use saved evidence where possible. Missing or incomplete observations
remain gaps rather than ranking losses. Paid research presents its specific
scope and estimate before asking for approval; some provider caps are best effort.
The tools that spend provider money are listed in [Paid MCP tools](/agents/paid-tools).

## Connect through MCP

bisibility exposes a Model Context Protocol (MCP) Streamable HTTP endpoint:

```text
https://your-host.example/api/mcp
```

Use `https://bisibility.com/api/mcp` for the hosted production endpoint. A
self-hosted client should use its own origin. Sign-in can happen on a regional
host such as `https://eu.bisibility.com` while the MCP endpoint stays at
`https://bisibility.com/api/mcp`, and the hosted MCP server reports the
application version `0.39.0` rather than the npm SDK version `@bisibility/sdk`
`0.14.1`.

Hosted MCP clients that implement the MCP OAuth flow discover bisibility's
authorization server automatically. The flow uses Authorization Code with PKCE,
dynamic client registration, and access tokens bound to the `/api/mcp`
resource. Automatically registered clients choose an access level before
approval. See [Agent permissions](/agents/permissions).

Clients that manage bearer credentials outside the MCP OAuth flow can still use
a personal access token or project API key. For example, connect Codex to a
self-hosted instance with a personal access token:

```bash
export BISIBILITY_TOKEN="bsb_pat_live_..."
codex mcp add bisibility \
  --url "https://your-host.example/api/mcp" \
  --bearer-token-env-var BISIBILITY_TOKEN
```

Project API keys work too. Other MCP clients use different configuration fields.

The MCP server card lists the endpoint and available tools:

```text
https://your-host.example/.well-known/mcp/server-card.json
```

## What each client exposes

Every client reaches the same endpoint and the same tool list. What differs
is where the URL is added, which tools the client shows, and how an action
is approved.

| Client | Adds the URL where | Write tools | Approval |
|-|-|-|-|
| Claude (web, desktop, Cowork) | Customize, Connectors, Add custom connector, then approve the sign-in | Every tool is exposed; no developer or write mode is required | Asks before each write tool the first time |
| ChatGPT | Plugins, +, Add custom MCP server; configure OAuth and install the plugin | bisibility requests read-only access for this connection | Workspace permissions and client confirmation settings apply |
| Claude Code | The `claude mcp add` command | Every tool is exposed | Follows the client's own tool-permission settings |
| Codex | The `codex mcp add` command | Every tool is exposed | Follows the client's own tool-permission settings |
| Cursor | Settings, MCP, then paste into `mcp.json` | Every tool is exposed | Follows the client's own tool-permission settings |
| Grok | Plugins, Connectors, New Connector, Custom, then approve the sign-in | Tools without `readOnlyHint` can stay hidden until write mode is on | Follows the client's own tool-permission settings. See [Agent permissions](/agents/permissions). |
| Grok Bot | Paste `Add the bisibility MCP server: https://bisibility.com/api/mcp` into a Grok Bot chat, confirm, then sign in from the connect card | Paid operations are write tools | Confirm the server, then approve sign-in. The consent screen may name the client Cursor. See [Agent permissions](/agents/permissions). |
| Other MCP clients | Any Streamable HTTP configuration with OAuth sign-in | Every tool is exposed | Follows the client's own tool-permission settings |

Each tool declares a `readOnlyHint` marker. Tools that never spend budget or
change data are marked read-only; clients that hide or gate write tools rely
on that marker. Paid operations such as rank checks and backlink analysis are
write tools; stored reports and cost estimates are read-only.

To update ChatGPT's tool definitions, refresh the plugin from its details page. Workspace
policies can restrict custom MCP servers. See OpenAI's [current connection guide](https://developers.openai.com/api/docs/guides/custom-mcp-server).
The bisibility consent flow narrows ChatGPT connections to read-only access.
See [Agent permissions](/agents/permissions).

### Connect Grok

1. On grok.com, open Plugins, then Connectors.
2. Choose New Connector, then Custom.
3. Name the connector `bisibility` and enter `https://bisibility.com/api/mcp`.
4. Sign in and approve the request on the bisibility consent screen.

Grok registers itself through dynamic client registration, then opens the
bisibility consent screen. The request can include every scope, including
`admin` and `tokens:write`. Approval grants the access level you choose.
Read and write is the default when it is offered, and API token creation stays
off unless you check it. See [Agent permissions](/agents/permissions). Paid
checks are listed in [Paid MCP tools](/agents/paid-tools).

Grok can hide tools that lack a `readOnlyHint` marker unless write mode is on.
The `get_session_profile` tool reports how many tools such a client shows; with
the current tool set that is 63 of 140. Turn on write mode in Grok to use the
write tools.

### Connect Grok Bot

Grok Bot is a separate client from the grok.com connector above.

1. Paste this instruction into a Grok Bot chat. Replace the URL when the MCP
   server is not the hosted production endpoint.

```text
Add the bisibility MCP server: https://bisibility.com/api/mcp
```

2. Confirm adding the custom MCP server.
3. Sign in from the connect card and approve access on the bisibility consent
   screen.

The consent screen may name the client Cursor and say the app was registered
automatically. That is expected for Grok Bot. Scopes, the access level, and
the API token checkbox are described in
[Agent permissions](/agents/permissions). Paid operations such as rank checks
and backlink analysis are write tools and charge the project's payment source.
Ask the bot to confirm the cost before it runs them. See
[Paid MCP tools](/agents/paid-tools).

## Authenticate

Choose a personal access token when the agent acts as you across projects or
performs account-level operations. Choose a project API key when the agent
should stay isolated to one project. Send either credential in the HTTP
`Authorization` header, not in a tool argument.

For hosted interactive clients, prefer the OAuth flow so the client never asks
the user to copy a long-lived API credential.

```text
Authorization: Bearer <token>
```

For REST clients and SDKs, set the API root and credential in the tool
environment. The `BISIBILITY_API_KEY` variable accepts either credential:

```bash
export BISIBILITY_BASE_URL="https://your-host.example/api/v1"
export BISIBILITY_API_KEY=placeholder
```

See [Authentication](/authentication) to choose and create a credential, select
a project for PAT requests, and make a test request.

## Run and save an SEO audit

The `seo-audit` skill guides your external agent's model through collecting real MCP data, prioritizing technical, content and visibility findings, and saving a project-local AgentReport. Bisibility supplies the tools and report storage. The model in your connected client performs the analysis.

Install the versioned plugin in Claude Code:

```text
/plugin marketplace add CorgiCorner/bisibility
/plugin install bisibility
/reload-plugins
```

Open `/mcp`, select Bisibility and sign in. Then run:

```text
/bisibility:seo-audit Audit my example.com project and save a prioritized report.
Use the free bounded crawl and saved ranking/AI evidence. Do not spend on providers.
Give me the report link and the first action.
```

For Codex and other Agent Skills clients, install the complete `plugins/bisibility/skills/seo-audit` directory from the [release repository](https://github.com/CorgiCorner/bisibility/tree/main/plugins/bisibility/skills/seo-audit), including its references and validation script. For Codex, place it in `~/.codex/skills/seo-audit`, connect MCP as shown above, and invoke `$seo-audit` with the same request. This plugin skill is distributed from the repository; the instance's generated tool-reference catalog is a separate discovery surface.

The workflow uses `list_projects`, `get_project`, `get_project_context`, `run_site_audit`, `get_site_audit`, `list_keywords`, `list_agent_reports`, `get_agent_report` and `create_agent_report`. It requires v0.28.0 or newer with these tools visible in the client's tool snapshot. A fresh crawl and report save need write scope plus project membership that allows writes. A read-only client can analyze stored data but must report that it could not crawl or save.

The crawler samples at most 15 pages within a 20-request, 15-second budget,
including robots reads, redirects and retries; each response body is limited
to 512 KiB. It does not render JavaScript or run Lighthouse. Read `state`,
`stop_reason` and `limitations` before drawing conclusions: `complete` describes
the bounded sample, not the whole site or verified search-engine indexing.
Persistent page 429 responses and unavailable robots policies produce partial
evidence; robots-disallowed paths are policy skips. Do not label a rate-limited
page as missing content or a broken link. See [Site Audit](/guides/site-audit)
for URL scope, retry behavior and saved-report reuse.

Reports retain source dates, partial crawl limits, missing data and uncertainty.
Saved AI Visibility evidence is provider-observed; Prompt Explorer responses
are synthetic tests and cannot establish real consumer visibility. Optional
paid enrichment uses an estimate followed by explicit approval of the operation
and cost cap, whether funded by your own provider key or deployment credits.

The skill saves bounded JSON/text with external kind `seo_audit` and returns `/app/<project_id>/agent-reports/<report_id>` on your app origin after confirming the save. This link inherits project access and does not publish the report publicly.

## Example workflow

1. Create or select a project.
2. Add a keyword with its country and device.
3. Start a rank check.
4. Poll the check until it completes.
5. Read the keyword's ranking history.

MCP tools use the same permission model as REST API v1 and expose the same
documented operations.

## More agent tasks

- Discover keywords that a domain already ranks for and annotate tracked terms.
- Research related queries, suggestions, and keyword ideas, then hydrate their metrics.
- Query live search-performance data or start an analytics sync.
- Generate a weekly report of ranking gains, losses, and new entries.
- Inspect, enable, or disable sitemap monitoring for a project.

## Optional DNS-AID records

HTTP discovery works without DNS-AID. Operators can publish DNS records when
they also want domain-level AI discovery:

```dns
_index._agents.your-host.example. 300 IN SVCB 1 your-host.example. alpn="h2" port="443" mandatory=alpn,port key65400="/.well-known/agent-skills/index.json" key65401="/api/v1/llms.txt"
_mcp._agents.your-host.example. 300 IN SVCB 1 your-host.example. alpn="mcp,h2" port="443" mandatory=alpn,port key65400="/.well-known/mcp/server-card.json" key65401="/api/mcp"
```

DNS-AID and DNSSEC are separate operator settings. Sign the zone and publish
the matching DS record before claiming authenticated DNS discovery. Verify the
records with a validating resolver.

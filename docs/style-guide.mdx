Use this page when writing or reviewing documentation. Canonical English stays
the source language. Do not add translations until there is evidence of demand.

## Voice

Write in second person (`you`). Use the imperative for steps: Create, Run,
Copy, Verify. Keep one action or claim per sentence. Stay factual. Do not use marketing filler.

The product name in prose is lowercase **bisibility**. Keep protocol names
literal: `Bisibility-API-Version`, `X-Bisibility-Signature`. Package names stay
exactly as published (`@bisibility/sdk`, `bisibility.com/sdk-go`).

Call the managed service **hosted Cloud**. Keep literal CLI and API identifiers,
such as `cloud import`, unchanged.

## Dates and global English

Use unambiguous dates (`9 September 2026` or `2026-09-09`). Avoid idioms,
humor, and culture-specific examples. Link with descriptive labels such as
[Authentication](/authentication). Do not use generic here-links.

## How-to template

```mdx
---
title: "Run a scheduled rank check"
description: "Schedule recurring rank checks for a project."
---

One sentence explaining when to use this guide.

## Before you begin

State only the required permissions, services, and credentials.

## Configure the schedule

1. Do the first action.
2. Do the second action.

## Verify

Explain exactly what successful completion looks like.

## Troubleshoot

Cover the one or two failures specific to this task.

## Next step

Link to the single most likely follow-up task.
```

## Reference template

Purpose, then syntax or schema, then fields, then constraints, then a minimal
example, then related reference. Do not hide a tutorial inside reference.

## Code samples

Snippets come from runnable `examples/` source or generated schema. Show 10-30
lines for one goal. Keep secrets in environment variables, especially
`BISIBILITY_BASE_URL` and `BISIBILITY_API_KEY`. After a sample, say what
success looks like.

Treat rendered samples as one of four classes:

- **Copyable quickstart:** complete imports, setup, operation, and output. The
  block must run from a fresh file after the immediately preceding setup
  steps.
- **Runnable repository example:** a longer program with helpers, cleanup, or
  assertions. Link it as a complete example.
- **Excerpt:** intentionally partial. Label it `Excerpt` and do not present it
  as a standalone program.
- **Generated API sample:** generated from OpenAPI and validated against the
  contract.

See [Versioning and support](/versioning) for app versus API versus client
versions.

## README presentation

Put the brand banner in its own paragraph, with a clear gap before the separate
badge rows. Keep navigation and capability badges
near the top. Preserve the clear demo link, short benefits and separate demo,
hosted and self-host paths. Place the application screenshot farther down as a
dashboard reference, at 560 pixels wide on desktop and shrinking on narrow screens.
Describe shipped capabilities and provider costs precisely; the demo link does
not imply signup-free access or included provider data.

The dynamic `CI gate` badge reads the `ci-ok` check run for the current public
`main` commit through the GitHub branch check-runs endpoint. A release-candidate
tag can run the check on that same commit. Link the badge to the public Actions
workflow so readers can inspect individual jobs; its label describes `ci-ok`,
whose dependencies define the gate. Status and status color come from the check
result. A security-policy link is not a security certification, and release
badges refer to published releases.

The `public/brand/readme-banner.svg` banner uses the standard mark and outlined
Geist lettering, with aligned product copy and a subtle decorative dashboard.
Its 1200 by 400 canvas displays at 900 by 300 pixels on desktop and scales down
on mobile. Preserve its aspect ratio, descriptive alt text and neutral palette.
The opaque white canvas uses the same monochrome treatment in light and dark
backgrounds: graphite lettering and subtle gray artwork. Every artwork color
has equal red, green and blue channels; avoid warm tints, colored shadows or
filters. The illustration communicates the interface without claiming
customer results.

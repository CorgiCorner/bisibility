# Detail rank snapshot

`loadKeywordDetailHistoryWindow` renews the session and membership, validates one project/keyword and a server-registered calendar window, and reads initial observation/attempt pages plus the header in one RepeatableRead snapshot. Initial `asOf` equals that window's end. A trusted synchronous projector receives an isolated copy of the first authorized targets/policy/project/source; it receives no database/write/provider port. Thenable results are rejected. Existing report reader DTOs remain compatible.

The current header uses `resolveCurrentRankTrackerTargets` and `projectRankTrackerQuality`. Independent current revision proof is required. Missing proof keeps current rank unknown; retained positive or unqualified reported values remain separately readable with their actual observation/recording dates. Latest logical attempt has its own recorded time, status and provider, independently of the retained current result.

Best is the minimum kernel-qualified positive position for one selected comparison key across the full retained read. Current-definition proof selects its current/last-success key; unavailable current proof selects the historical resolution key and labels Best as last-known-definition. Target/policy/identity, provider and normalization boundaries stay in that key. No old definition is substituted for a verified new definition lacking matching data. Best may be stale and is labeled as a retained historical value, never a freshness/KPI substitute. Missing observation time or method gives no comparable Best. Read budgets fail with a 413 rather than taking only 90 or returning a partial minimum.

Numeric movement uses only the shared kernel's supplied comparable pair and movement. Entry/exit/first/unknown events are not numeric 101 subtraction. Baseline tolerance, current boundary and freshness come exclusively from the actual server metadata/policy port. Search metrics use the first typed captured metadata result from this same transaction; absent capture sets known flags false and never uses legacy raw enrichment.

The installed route supplies the quality sidecar to both normal and pending headers. The old detail loader supplies editable context and unrelated traffic only; its rank fields are overwritten before header consumption. Existing consumers without a sidecar keep their compatibility rendering. Per-check expected/ranking URLs use the history workspace's observation page and follow that workspace's window/cursor; there is no second static 90-record URL card.

Header `asOf` stays visible when a later user-triggered history-only window refresh obtains a newer snapshot. A route refresh recreates both together. Raw diagnostic/explicit extension controls and CSV/export bridge remain separate workflows; they do not supply header evidence and this contract does not claim their report-export migration complete.
